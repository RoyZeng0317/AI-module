# 2026-08-13 修正完畢：lib/main.py 匯入 camera/command/conversation 失敗

## 對應錯誤（見 Agent/ErrorLog/2026-08-13.md 更新後版本）
```
Import "camera" could not be resolved (from main.py) [ln 15, col 6]
Import "command" could not be resolved (from main.py) [ln 16, col 6]
Import "conversation" could not be resolved (from main.py) [ln 17, col 6]
```

## 根本原因（不只是 Pylance 誤報，實際執行也會壞）
用 `python -m lib.main` 實際跑一次，直接重現 `ModuleNotFoundError: No module named 'camera'`，
確認這不是單純 Pylance 快取問題，是兩個真的 bug：

1. **`lib/main.py` 第 15-17 行還是搬家前的裸匯入**：`from camera import CameraPanel`
   這幾行是從 `app/components/main.py` 搬到 `lib/main.py` 時沒跟著改。同目錄的
   `command.py`／`conversation.py` 內部早就已經改成 `from lib.components.xxx import ...`
   這種絕對匯入寫法（見 `lib/components/command.py:21-24`、
   `lib/components/conversation.py:36`），只有 `lib/main.py` 這個入口檔案沒跟上。

2. **`sys.path.insert` 的相對路徑層數也沒跟著搬家更新**：原本第 11-13 行是
   `os.path.join(..., "..", "..", "FileConvert"/"tranning"/"web/backend")`，這是
   `app/components/main.py`（往上兩層才到專案根目錄）時期的寫法。`lib/main.py`
   往上只需要一層就是專案根目錄，多一層 `..` 會算到
   `C:\Users\Roy\Documents\GitHub\`（AI-module 的上一層，不存在 tranning/web），
   導致 `tranning`、`web/backend` 都沒被加進 `sys.path`——這也是為什麼修好
   第 1 點之後，`lib/components/camera.py` 裡 `from detector import detect`
   （`detector.py` 在 `web/backend/`）還是找不到模組。

## 修正內容（`lib/main.py`）
- 第 11-13 行：`"..", "..", ...` 改成 `"..", ...`（少一層），讓
  `tranning`、`web/backend` 正確指到 `AI-module/tranning`、`AI-module/web/backend`。
- 第 15-17 行：改成跟 `command.py`/`conversation.py` 一致的絕對匯入
  ```python
  from lib.components.camera import CameraPanel
  from lib.components.command import CommandPalette
  from lib.components.conversation import Conversation, is_recording, start_recording, stop_recording
  ```

## 順手補的環境缺口
沿著匯入鏈往下跑到底時，另外發現 `.venv` 沒裝 `pymupdf`（`fitz`，ErrorLog.md
第 10 點已知缺口）跟 `sounddevice`（`conversation.py` 用來錄音），一併
`pip install pymupdf sounddevice` 讓整條匯入鏈能真的跑到底。
