# Sinco 情緒回應修正與 Claude Code 交接

使用者需求：「我今天心情不好」應回覆「你怎麼了？」這類先關心、再邀請說明的內容。

本次修正明確的短句回覆流程，沒有重訓模型，也未與即時 Claude Code 工作階段直接通訊。使用者可將此文件交給本機 Claude Code 接續。這是本機句型規則，不代表神經網路已學會自由敘述的情緒理解；trace 會明確標示「非模型生成」。

## 重現結果

使用 GitHub 現有 tranning/MentalHealth/emotion_runs/best_model.pt 實測，eval 分數：

| 輸入 | 舊情緒模型分數 | 舊標籤 |
| --- | --- | --- |
| 我今天很開心 | 3.94 | 偏正向 |
| 我今天不開心 | 3.55 | 偏正向（錯誤） |
| 我不難過 | 1.56 | 偏負向（未處理否定） |
| 我很難過 | 1.98 | 偏負向 |
| 請解釋什麼是難過 | 1.96 | 偏負向（沒有區分提問與自述） |

這是單次 checkpoint 的具體案例，不是整體準確率估計。MC Dropout 的一致率不能證明標籤正確。

舊 persona_chat.match_example() 能把「我今天不開心」配到「我今天開心」（相似度 90.9%）、「我不難過」配到「我難過」（85.7%）、「我不想聊天」配到「我想聊天」（88.9%）。範例比對直接回原句，沒有使用情緒模型過濾意思相反的結果。

一般聊天原本只呼叫 Transformer 生成回覆；情緒模型輸出只附在 trace，並不參與內容選擇。沒有一般聊天 Transformer 權重，不能在雲端重現它的原始生成內容。

## 已完成

- 新增 tranning/emotion_response.py，只辨識明確、自述的短句與明確不想談的需求。
- 一般聊天：明確情緒短句走本機規則，其他訊息保持原本模型路徑。即時工具、手動 code／nvidia 模式仍依既有路由。
- 角色聊天：適當的使用者自寫範例優先；沒有範例時，明確情緒短句先得到關心回覆，不會依個性加玩笑語尾或表情符號。
- 角色模糊比對：保留否定詞及其鄰近範圍，擋下否定改變或已辨識的相反情緒。英文否定在去掉空白／標點之前檢查，避免 not 的詞邊界消失。
- 明確句型的角色 trace 不再附上相反的情緒模型標籤，清楚標示句型判斷。

## 實際行為

| 輸入 | 回覆 |
| --- | --- |
| 我今天心情不好 | 你怎麼了？願意跟我說說發生什麼事嗎？ |
| 我今天不開心 | 你怎麼了？願意跟我說說發生什麼事嗎？ |
| 我不難過 | 了解。想聊的時候再跟我說就好。 |
| 我今天心情很好 | 聽起來心情不錯！有什麼開心的事想分享嗎？ |
| 我今天心情不好，不想聊 | 好，先不追問。想聊的時候再跟我說就好。 |

有相近句型，例如「我覺得很難過」「今天我心情不好」「我好想哭」。這是有限範圍的規則；未知敘述仍交給原本模型。引用、第三人稱、複雜否定、混合情緒及其他續句不依單一情緒詞推斷，例如「我朋友很難過」「我不是不開心」「我心情不好，但現在好多了」不會命中這條規則。這些輸入的原本模型回覆品質尚未解決。

## 測試與接續

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -m pytest -q tranning/test_emotion_response.py tranning/test_persona_chat.py tranning/test_chats.py tranning/MentalHealth/test_action.py
```

最後結果請見交付包 test-results.txt。測試包含使用者例子、正負與否定對比、不想談的界線、第三人稱／引用／混合感受不誤觸發、角色範例優先、英文否定及手動模式／工具路由。

本機接續：先用 GUI／CLI 測試表格內的句子，確認實際呼叫 smart_reply_traced() 的版本已更新。再整理未命中的真實例子，包含使用者輸入、實際回覆與期待回覆，建立人工評分的獨立測試集。情緒模型目前只輸出 0~5 正負向分數，不能單靠它區分悲傷、焦慮、生氣、第三人稱或「先不要問」等不同需求。若要進一步改善模型，需要這些語義對比資料及本機 Transformer 權重進行獨立評估與訓練。

本次不修改模型權重、不把情緒規則混入神經網路準確率。過擬合評估修正另見 PR #5，兩者可獨立合併。
