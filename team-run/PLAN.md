# 本次工作計畫

## Restatement & Success Criteria

使用者需求：修正文不對題、改善一般正常問答、保有上網查詢能力，以及加強實際由後端供應的網頁介面。共用對話流程仍放在 `tranning/chats.py`，資料查詢沿用 `tranning/tools.py`，不得改接其他 AI 模型或雲端 LLM API。

成功條件：
- 一般問候、能力詢問與明確知識問題不再因寬鬆關鍵字被送到錯誤工具或程式碼分支。
- 對未能可靠回答的內容明確表達能力限制；不以不相關的訓練樣本冒充答案。
- 明確搜尋及需要即時資料的提問能取得可辨認的網頁資料與來源；失敗有可理解的回覆。
- 桌面、CLI、Web 維持單一共用路由；Web 正確傳遞既有必要參數。
- 實際供應的 `web/admin/frontend/` 採清楚、深色、響應式設計，保留原有聊天、登入與其他功能掛鉤。
- 必要回歸測試通過，現有灰階、特徵與曲線修改保留；不宣稱已藉此次修正訓練出一般人類等級的語言理解。

假設：本次授權為程式修正與必要測試，不包含長時間正式模型訓練、大量下載或替換 checkpoint。信心：高。

## Open Questions for the User

無。既有範圍足以先執行；介面採深色、可讀與手機適配。真實一般問答能力仍受既有訓練語料與 checkpoint 限制，應於交付說明。

## Approach & Verification per Sub-task

- S1：讀取 AGENTS.md、README.MD、相關待辦與錯誤紀錄；檢查 git diff，確認 backend 的 FRONTEND_DIR。僅在專案內修改，不讀改 `.env`。
- S2：沿 `smart_reply_traced()`、`route_reply()` 與 `/api/chat` 追蹤一般問候、未見問法、程式碼要求、即時查詢及明確搜尋。優先重現可修正的分支錯誤；不更動模型訓練成果。
- S3：小幅修改已證實的根因，保留手動模型選擇與工具優先順序。測試涵蓋語意相近但目的不同的輸入、空結果／超時、來源顯示及不觸發雲端 AI。網路測試採固定回應驗證，不依賴外站穩定性；如做即時 smoke test，另列實測範圍。
- S4：先讀 HTML、CSS、action.py、script.js，保留既有 ID 與事件。調整資訊層級、對話閱讀寬度、輸入區、側欄及窄螢幕；提供載入、查詢與錯誤狀態。驗證靜態服務、關鍵掛鉤及可行的瀏覽器檢查；無視覺檢查時明說。
- S5：審查者檢查回歸風險與來源可信度，修改後跑相應測試，不執行整個昂貴訓練套件。交付區分「修正路由／查詢／介面」與「模型仍須語料與訓練」。遇到錯誤依規則記錄 ErrorLog.md；未經使用者確認不自行宣告已完成修正日誌。

## Unknowns for Research

- 現有 checkpoint、檢索相似度與回覆品質判斷如何造成文不對題；是否存在已知回歸案例。
- 既有網路查詢供應者是否能無金鑰運作，以及返回來源、失敗與超時機制是否完整。
- Web 所需的上下文、模型選擇及 tracing 是否與桌面一致。
- 前端實際依賴的 DOM ID、PyScript 載入順序及行動版限制。

## Stop Conditions

- 如需讀寫 `.env`、移出專案修改或使用其他雲端 AI，停止該路徑並維持本地修正方案。
- 如需真正長時間訓練、覆寫 checkpoint 或大規模下載才能繼續，先完成可驗證的程式修正，再將訓練列為需要獨立授權的後續工作。
- 發現未提交修改與必要變更直接衝突時，不覆蓋原成果；保留內容並協調整合。
- 測試通過且獨立審查無阻擋問題即可交付，不以增加訓練或無關重構延長本次範圍。
